항목 결과
성능 road 평균 20.000 FPS, model 평균 19.983 FPS, model execution 평균 30.670 ms, p95 33.424 ms
이전 plannerd PSS 75,805 KB에서 366,374 KB로 증가
분류 bench runner 때문에 생긴 가짜 증가가 아니라, 실제 runtime 증가였습니다. 이후 microbench로 MPC solver 자체는 배제했습니다.
당시 관찰 config_realtime_process()가 Python GC를 끄는 경로였습니다. GC on full probe는 안정적이었고, GC off full probe는 110초에 PSS 51,720 KB -> 188,094 KB로 증가했습니다.
최종 정리 이후 실제 원인은 보드 venv의 pycapnp 2.2.2와 GC-off 조합으로 좁혀졌습니다. repo pin인 pycapnp 2.1.0에서는 같은 메시징 probe가 cyclic garbage 0개였으므로, realtime.py GC gate 실험은 제거했습니다.

작업 이력

  1. 초기 RK3588 벤치 MVP

    초기 authoritative repo는 orangepi@192.168.219.113:/home/orangepi/openpilot였고, 유선 연결 후 현재 주소는 192.168.219.114입니다. 보드 checkout은 master, 4532320fb에서 시작했습니다.

  2. USB webcam 경로 확정

    native camerad/MIPI 대신 USE_WEBCAM=1 + Python webcamerad를 사용합니다. 검증된 기본값은 ROAD_CAM=0, 1280x720, MJPG, 25 FPS입니다. WEBCAM_FOURCC는 4글자일 때만 적용하고, 잘못된 값은 fallback합니다.

  3. tinygrad/OpenCL 경로 폐기

    tinygrad DEV=CL은 간단한 tensor smoke에서는 동작했지만 실제 모델 경로에서는 안정적인 대안이 아니었습니다. 현재 실사용 포팅 경로는 tinygrad를 버리고 직접 OpenCL 전처리 + RKNN 추론 조합입니다.

  4. RKNN 변환 감사

    변환 후보였던 /tmp/rknn-audit/driving_supercombo_gelu19_imgfp16_fp16.rknn를 기준으로 ONNX 전/후와 RKNN 출력 정확도를 확인했습니다. 배포 모델은 /home/orangepi/.openpilot/models/driving_supercombo_rk3588.rknn입니다. artifact 교체 때마다 코드 수정이 필요하지 않도록 RKNN SHA 검사는 포팅 코드에서 제거했습니다. 대신 wrapper는 파일 존재와 RKNN/OpenCL runtime을 확인하고, modeld는 RKNN input/output attr와 byte-size를 런타임에 검증합니다.

    정확도 복구에 필요했던 핵심 ONNX rewrite는 두 가지였습니다. 첫째, linear_6 -> ReduceL2 -> Div에서 fp16 제곱합 overflow를 피하기 위해 sqrt(sum((x / 4)^2)) * 4 형태로 바꿨습니다. 둘째, p-branch 음수 GatherND가 RKNN에서 깨져서 의미가 같은 Slice(fb_full, axis=1, 16:25)로 바꿨습니다.

  5. RKNN 정확도 최종 값

    기존 변환 리포트 기준 최종 FP16 RKNN 후보는 7개 감사 샘플에서 finite output 7 / 7, worst cosine 0.980182, worst relative MAE 0.14816, steady NPU runtime 29.83 ms였습니다.

  6. OpenCL YUV6 warp 추가

    모델 입력 전처리는 tools/rk3588/opencl_yuv6_warp.cpp와 openpilot/selfdrive/modeld/opencl_warp.py를 사용합니다. wrapper가 /home/orangepi/.openpilot/lib/libopencl_yuv6_warp.so를 준비합니다. RGA와 OpenCL 경로의 동치성을 확인한 뒤, 실사용 경로는 직접 OpenCL로 정했습니다.

  7. UI preview와 overlay 보정

    webcam intrinsic을 openpilot/common/transformations/camera.py의 webcam config로 고정하고, UI preview와 augmented road overlay가 1280x720 webcam frame을 기준으로 동작하도록 조정했습니다. BIG UI는 BIG=1로 켭니다.

  8. 메모리 문제 원인 확인: plannerd/pycapnp

    수동 gc.collect()는 근본 해결이 아니었습니다. comma/TICI 경로와 비교해 보니 RK3588 PC 경로에서 modeld에 config_realtime_process(7, 54)를 그대로 적용하면 PSS가 빠르게 GB 단위로 커졌습니다. 당시에는 modeld realtime opt-out을 임시 회피로 확인했지만, 최종 원인 확인 뒤 제거했습니다.

    이후 남은 장시간 memory slope는 modeld realtime 이슈와 별개로, plannerd를 직접 interpreter로 띄운 분리 테스트에서도 재현되었습니다. 처음에는 LongitudinalMpc.set_weights() 반복 호출을 의심했지만, LongitudinalMpc 단독 microbench에서는 1000회 반복에도 PSS 증가가 재현되지 않았습니다. 이후 더 작은 probe로 실제 원인은 pycapnp 2.2.2가 GC-off 조건에서 capnp schema 객체 순환 참조를 대량 생성하는 문제로 좁혔습니다. 보드 venv를 repo pin인 pycapnp 2.1.0으로 맞춘 뒤에는 같은 probe에서 cyclic garbage가 0개였고, realtime.py GC gate 실험은 제거했습니다.

  9. 20 FPS 최적화

    초기 RKNN 실행은 model period 평균 약 54.1 ms로 20 FPS에 못 미쳤습니다. OPENPILOT_RKNN_CORE_MASK=7이 mask 0, 3, 65535보다 안정적이었고, RKNN input queue를 float16으로 바꿔 매 frame pack cost를 줄였습니다. 그 결과 60초 bench에서 model execution p95가 49.436 ms까지 내려갔습니다.

    이후 modeld/webcamerad만 RK3588 big cores 4-7에 두고 UI는 제한하지 않는 affinity를 적용했습니다. 5분 bench 기준 road 평균 20.000 FPS, model 평균 19.983 FPS, model execution p95 35.716 ms까지 개선되었습니다.

  10. 메모리 문제 원인 확인: modeld/RKNNLite

    장시간 BIG UI 실행 중 보드가 멈춘 뒤 재부팅하고 모니터링을 붙여 재현했습니다. 처음 10분 run에서는 modeld PSS가 수십 초 안에 GB 단위로 증가했고, UI나 webcamerad가 아니라 modeld가 freeze 원인임을 확인했습니다.

    rknn-toolkit-lite2의 Python wrapper 경로를 버리고 /usr/lib/librknnrt.so를 ctypes로 직접 호출하는 openpilot/selfdrive/modeld/rknn_policy.py를 추가했습니다. 새 wrapper는 실제 RKNN artifact의 input/output attr를 query해서 features_buffer가 1x24x512인 것을 기준으로 맞추고, 매 추론마다 output copy 후 rknn_outputs_release()를 항상 호출합니다.

    같은 모델을 C API 단독 probe로 100회 반복했을 때 PSS가 약 173 MB 근처에서 고정됐고, openpilot 10분 BIG UI full bench에서도 modeld PSS가 plateau를 보였습니다.

  11. 장시간 안정성 검증

    MALLOC_ARENA_MAX, MALLOC_TRIM_THRESHOLD_, PYTHONMALLOC=malloc, UI FPS=30은 각각 성능을 떨어뜨리거나 메모리 slope를 충분히 줄이지 못해 기본값으로 채택하지 않았습니다. 최종 채택된 방법은 RK3588을 /TICI로 흉내내거나 modeld realtime을 끄는 것이 아니라, 보드 dependency를 pycapnp==2.1.0으로 repo pin에 맞추고, RKNN 추론은 직접 C API wrapper로 실행해 output release를 명시하는 것입니다. 이 경로에서 10분 BIG UI full bench가 bench_rc=0, metrics_rc=0로 끝났고, 최신 run /home/orangepi/rk3588_debug_runs/big_pipeline_20260704_185607 기준 publish period 평균 50.000 ms, model execution p95 37.134 ms, frame drop 평균 0.000을 확인했습니다. modeld RSS는 약 531 MB에서 543 MB 범위였고, SHUTTING_DOWN signal handler는 제거해 upstream의 KeyboardInterrupt 종료 경로로 되돌렸습니다.

TICI 타깃화와 메모리 누수 검토

2026-07-04에 RK3588을 TICI처럼 공식 타깃으로 보이게 만들면 메모리 누수가 없어지는지 검토했습니다. 결론은 /TICI 에뮬레이션은 정답이 아니고, plannerd/GC-off 문제는 보드 venv의 pycapnp 버전을 repo pin과 맞추는 것이 직접 대응한다입니다. 이후 별도로 확인된 modeld freeze 원인은 RKNNLite Python wrapper 쪽이어서, 현재는 rknn_policy.py의 직접 C API 경로로 처리합니다.

  • openpilot/common/hardware/__init__.py는 /TICI 파일 존재만으로 TICI=True, PC=False를 결정합니다.
  • TICI로 바꾸면 qcomgpsd, ubloxd, pigeond, modem, sensord 같은 Qualcomm/TICI 전용 경로가 켜집니다. RK3588 보드에는 맞지 않는 방향입니다.
  • plannerd는 TICI에서도 동일하게 Python process이고 config_realtime_process()를 탑니다. 따라서 타깃 식별만 바꿔도 GC/pycapnp 누수 조건이 사라지는 구조가 아닙니다.
  • 보드 venv는 처음에 pycapnp 2.2.2였지만, repo의 pyproject.toml과 uv.lock은 pycapnp==2.1.0을 고정합니다. 주석에도 2.2 introduces a memory leak due to cyclic references라고 명시되어 있습니다.

검증 결과

조건 결과
pycapnp 2.2.2, GC off, messaging.new_message(...).to_bytes() 60,000회 PSS가 약 20MB에서 1.8GB까지 증가했고, 수동 collect 시 capnp.lib.capnp._StructSchemaField 중심의 cyclic garbage 약 924만 개가 확인되었습니다.
pycapnp 2.2.2, GC on, 같은 probe PSS가 약 22MB 수준에서 plateau를 보였습니다. 즉 수동 gc.collect() 문제가 아니라 GC disabled 조건에서 pycapnp 2.2 순환 객체가 누적되는 문제입니다.
pycapnp 2.1.0, GC off, 같은 probe PSS가 약 23.9MB로 고정됐고, gc.collect() 결과 cyclic garbage가 0개였습니다.
pycapnp 2.1.0, GC off, RKNN/OpenCL bench webcamerad,modeld,calibrationd,plannerd bench가 exit 0. 정리 전 확인에서는 plannerd PSS가 약 29.9MB에서 34.3MB까지의 작은 초기 증가만 보였고, hardcoded intrinsic 전환 후 35초 smoke에서는 model execution 평균 33.096 ms, publish period 평균 50.007 ms, frame drop 0이었습니다.
직접 RKNN C API wrapper, 10분 BIG UI bench bench_rc=0, metrics_rc=0. modeld PSS plateau, model execution 평균 34.839 ms, publish period 평균 50.000 ms, frame drop 0.

이 검토 이후 보드 venv는 pycapnp==2.1.0으로 맞췄고, openpilot/common/realtime.py의 GC opt-in 실험 패치, wrapper의 GC 관련 실험 export, modeld realtime opt-out env, bench runner의 legacy Params monkeypatch를 제거했습니다.

다시 하지 말 것

  • big_driving_supercombo.onnx는 이 포팅 경로에서 사용하지 않습니다.
  • tinygrad CL 실험 경로는 현재 실사용 경로가 아닙니다. 직접 OpenCL warp + RKNN을 사용합니다.
  • 메모리 문제를 수동 gc.collect()로 덮지 않습니다. 보드 venv의 pycapnp는 repo pin인 2.1.0으로 유지합니다.
  • prebuilt marker를 쓰레기 파일로 보고 지우지 않습니다. wrapper가 전체 SCons 빌드를 피하기 위해 관리합니다.
  • 문제 해결을 위해 controlsd, panda safety, car interface를 건드리지 않습니다. 현재 작업은 runtime/bench/vision/modeld/UI preview 포팅 범위입니다.
  • 검증 후에는 PYTHONDONTWRITEBYTECODE=1을 쓰거나 __pycache__를 정리하고 상태를 다시 봅니다.
